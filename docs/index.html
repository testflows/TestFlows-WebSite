Stop hoping the bug happens again.


Race conditions, timing issues, and network failures show up once in a while, and almost never when you are looking for them. Machine runs your real, unmodified Linux x86_64 software, from a single binary to a Docker Compose project, in a machine that controls time, interrupts, random numbers and the thread schedule. Every run can be replayed exactly and branched from any point.


So instead of running a test thousands of times, you name the race and make it happen.

See a missed wakeup forced and fixed →













From a failure to a verified fix.






01


Record every run


Every run is recorded as it executes. A replay repeats it exactly, to the instruction, as often as you like.

Replay →





02


Branch from any point


Checkpoint the whole machine and fork a branch from any point. Each branch goes its own way while the original stays as it was.

Checkpoints and branches →





03


Force the bug


Hold a thread in a race window, fail the exact system call, or delay a packet, and make the machine produce the failure the code points at.

Steering programs →





04


Debug at any point


Read registers, memory and the stack, set breakpoints and watchpoints, or run GDB inside the machine, at any point of any run.

Debugging →





05


Verify the fix


Run the same interleaving against your fix. When it passes, you know the fix holds, not just that the failure has not shown up yet.

See an example →

















Built for AI agents. Controlled by you.


Agents do the heavy lifting, while you stay in the loop and can see every step they take, repeat it, and take over at any point. Your agent drives Machine through the same machine client that you use, and the Python SDK gives both of you full programmatic control.


Install the Machine skill, ask your agent what Machine can do for your project, and it sets things up with you.



Get the Machine skill
Guide for AI agents














A deterministic hypervisor is only the beginning.


A complete deterministic simulation testing system manages recordings, checkpoints and branches, controls execution, injects faults, debugs failures and explores schedules, and makes all of it work together reliably. Machine provides the whole system and runs it for you as a cloud service.














Your first run in five minutes.


Drive Machine from your terminal with the machine client, from your programs with the Python SDK, or let your coding agent drive it with the Machine skill. The same commands, either way.

Why Run Bombadil in a Deterministic Hypervisor?
Bombadil is a property-based testing tool for web and terminal UIs. It allows you to describe how your application should behave and what actions can be taken to interact with it using a TypeScript specification. Bombadil uses this specification to explore your application, selecting and performing actions based on its current state while checking your properties along the way. You can run it in your local development environment, in CI, or inside Antithesis. Naturally, we also wanted to see how it would run inside Machine, our deterministic hypervisor behind the TestFlows Machine simulation testing environment. Inside Antithesis, though, Bombadil runs differently because it is integrated with their fuzzer. What we can do is run Bombadil much as you would run it locally, but deterministically. ...
