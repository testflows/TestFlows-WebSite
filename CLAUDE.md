# CLAUDE.md

Guidance for writing on this site: the TestFlows Machine docs in
`source/docs/machine/`, their agent entry files in `source/_md/`, and the rest
of `source/`. `docs/` is generated by `npx hexo generate`; never edit it by
hand.

## Writing style

The docs are read by developers and by AI agents. A person reads a page top to
bottom; an agent often reads one section alone. Write for both.

- **Concise is good.** Developers don't want paragraphs explaining something
  that takes one sentence.
- **Dry is acceptable in command references.** Readers go there for answers,
  not entertainment.
- **Awkward or overly compressed language is not good.** Saving five words isn't
  worth making the reader mentally reconstruct a sentence. Not "It checks each
  against the recording. A mismatch is a divergence." but "During replay,
  Machine checks each entry against the original recording. If they don't
  match, Machine reports a divergence."

Write as an experienced engineer explaining the system to another engineer.

- **Professional, not playful.** No colloquial images such as "a whole trip".
  Natural sentences and transitions are welcome; jokes and slang are not.
- **A heading names its subject.** "Comparing entries", not "What led up to
  it"; "Clock rate", not "How fast it passes". A heading is read alone in
  a table of contents and by an agent, where "it" names nothing.
- **Each section stands alone.** Name the command, flag or run instead of "it"
  or "the above" when the referent is in another section.
- **One word per thing.** Use the command's own word: `fork` forks, a child run
  is a branch, a saved state is a checkpoint, a location in a run's history is
  a point. Never a synonym.
- **State prerequisites before the steps,** and say what a command changes.
- **Every example runs as written.** Example output is copied from a real run,
  never invented.
- **A number carries its context:** what was measured, against what.

## Changes

- Change only the pages and sections asked for. A broad pass over the site is
  not reviewable.
- `source/docs/machine/commands.md` is generated from the CLI's help by
  `tools/website_commands.py` in the Machine repository. Fix its wording in the
  CLI help, then regenerate; an edit here is lost on the next run.
- Run `python3 tools/check_docs_md.py` after editing the Machine docs.
- No Claude attribution in commit messages: no `Co-Authored-By`, no session
  links.
